# 观澜 · 零售经营分析智能体

面向零售门店每周销售复盘，提供销售查询、门店比较、下降排名、历史趋势和循证排查。Python计算数值，DeepSeek选择工具，Streamlit呈现交互与图表。

## 云端试用版

部署入口为仓库根目录的`streamlit_app.py`，Python选择3.12。原程序保留在`1/`目录；根目录配置为Streamlit Community Cloud准备。

默认演示数据由本项目独立生成：20家虚构门店、26周、520条记录，2025-01-03至2025-06-27，金额单位元。销售额与节假日标记均为虚构，不代表真实商家或实际经营成效。页面、报告与模型上下文均说明数据性质。

来源及生成方法见[演示数据说明](1/data/演示数据说明.md)，生成程序见`1/scripts/generate_demo_data.py`。本发布包不含Walmart课程CSV、本机密钥、运行日志或旧版截图。

## 首次发布

1. 将此目录内的文件与文件夹上传至现有GitHub仓库根目录，保留`1`目录层级。不要额外套一层发布包文件夹。
2. 在Streamlit Community Cloud选择现有仓库，分支`main`，入口`streamlit_app.py`，Python3.12。
3. 第一次可以不配置任何密钥，先发布并验证免费规则练习、筛选分析、下降诊断和导入功能。
4. 需要真实模型对话时，在云平台的Secrets单独配置下述内容。实际值由账号所有者填写，不上传GitHub，不在聊天中发送。

```toml
DEEPSEEK_API_KEY = "填写你自己的密钥"
DEEPSEEK_MODEL = "deepseek-flash"
APP_ACCESS_CODE = "设置独立的评委试用口令"
APP_DAILY_REQUEST_LIMIT = 100
```

云端仅在同时配置试用口令和模型密钥时启用站点模型服务。访问者不需要输入开发者密钥；云端页面不提供密钥或模型修改框。配置口令后，所有页面均需输入口令才能进入。

## 计数、数据与使用边界

- 每会话最多30次模型请求，每个问题最多5次。单个运行实例内另有共享UTC日请求上限，默认100次；失败请求也占用上限。
- 共享上限不是人民币预算封顶，重启、休眠后实例重建或清除缓存可能使计数重置。真实费用以模型服务商控制台为准；评审期间需核对余额和用量。
- 上传CSV仅保存在当前会话内存，重启或新会话后需重新上传。模型对话会发送分析所需的统计结果和部分逐周记录。
- 恢复默认数据会回到虚构样本，保留模型请求计数并清空旧数据的对话与经营补充。
- 诊断给出待核实线索，不把虚构设定、手动填报或相关性当作已确认原因。当前没有销售预测模型。
- 经营知识使用固定诊断类别匹配，来源保存在知识卡片中，不是实时联网检索。
