# 观澜 · 零售经营分析智能体

以每周销售复盘为场景，支持销售查询、门店比较、销售下降排查、经营信息补充和知识依据展示。

Python与pandas负责计算，Streamlit负责交互界面，DeepSeek接口负责理解问题、调用工具和解释结果。

## 当前状态

这是用于首次上传GitHub的代码副本。完整应用已在开发者本机运行；此仓库尚未完成云端部署。

**该副本不包含销售CSV，也不包含API密钥。直接部署尚不能完成分析。**

程序当前仍默认读取`data/Walmart_Sales.csv`。原课程数据的再发布许可待确认，因此没有加入此副本。正式上线前需明确数据许可或改用可再发布的数据，并完成相应适配与测试。现有上传入口在默认数据加载之后，不能仅靠上传文件绕过默认数据缺失。

`.streamlit/config.toml`目前仍保留本机监听配置。部署JoyCode时需另行配置云端启动方式、监听地址与端口，完成真实部署验收。

## 目录

- `app.py`：应用入口。
- `analysis.py`、`diagnosis.py`：销售分析和下降排查。
- `agent.py`：DeepSeek工具调用。
- `knowledge.py`、`data/retail_knowledge.json`：经营知识与来源。
- `interface.py`、`cover.py`、`knowledge_ui.py`、`assets/`：界面与素材。
- `data_import.py`、`data_import_ui.py`：CSV校验与切换。
- `tests/`：自动检查；部分检查依赖未随仓库发布的课程数据。

## 使用边界

下降排查提供有依据的线索和核查步骤，不将相关性认定为实际原因；手动填写的经营情况标为未独立核验。当前没有销售预测模型。

知识库包含公开资料的简短中文整理和项目核查规则，来源链接保存在各条知识中；知识与诊断通过固定类别关联。

## 配置与更新

密钥在本机或云平台单独配置，不上传GitHub。当前支持`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`和`APP_ACCESS_CODE`。

本机原项目继续作为主要开发版本。此目录是上传副本，在GitHub编辑文件后应及时同步回主要开发版本，避免两份代码不一致。

计划更新流程：本机修改与验收 → GitHub同步 → JoyCode取得新版代码 → 发布已有应用的新版本 → 检查评委网址。
